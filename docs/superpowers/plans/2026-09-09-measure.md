# The measure of the first real agent (#101) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Speak the liturgy N times to a real model (`claude-opus-5`) on the live host, check the seven postconditions of spec §11 against `list` and the verbs, and record every transcript, every `list`, the token counts and the verdict under `docs/embryo/`.

**Architecture:** One new module, `membrane.measure`, exposed as the console script `measure`. It reads the operator's `.env`, hatches with `embryo/hatch.sh` (`MEMBRANE_MODEL=anthropic`), speaks each turn of `embryo/liturgy.md` through the right door over HTTP, approves pending proposals (automatically, or by asking the pilot on stdin), waits for builds, repairs failed builds with turn 3, checks the postconditions, writes the evidence directory, and tears the brain down so the next run starts from nothing. The membrane's audit line grows a `usage` field so the token counts come from the Anthropic responses themselves and reach the transcript through mshkn's `exec_log`, not through a side channel.

**Tech Stack:** Python 3.12, httpx, the membrane package (`embryo/`), `ssh-keygen`, the live host.

**Spec:** `docs/superpowers/specs/2026-09-08-embryo-design.md` §11 ("The measure of the first real agent") and §12; issue #101.

## Global Constraints

- uv is the only package manager; every tool runs as `uv run <tool>`; the gate is `uv lock --check && uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest --cov` with `fail_under = 98` and zero warnings.
- `tests/unit/test_docs.py` fails when a document names a path, route or variable that does not exist; `docs/embryo/README.md` joins its `DOCS`.
- The model keys are read from `.env` (git-ignored) or the environment and are never written anywhere but the brain's `/brain/.env` (which `hatch.sh` already does) and never printed.
- No test is weakened; the E2E gate line stays 166 passed, 6 skipped, 4 failed over 176 tests.
- Pricing used for the cost column, from the Claude API reference cached 2026-06-24: `claude-opus-5` $5.00 per million input tokens, $25.00 per million output tokens; cache writes 1.25x input, cache reads 0.1x input.

## Decisions

| # | Question | Decision |
|---|---|---|
| 1 | Where does the driver live? | `embryo/membrane/measure.py`, console script `measure`. It is root's tool and runs on the operator's machine, never in the brain; it lives in the package so it is typed, linted, covered and importable by the unit tier, and reuses `membrane.config.parse_env`. |
| 2 | Where do the token counts come from? | `AnthropicModel.complete` keeps `response.usage`; the loop sums it over its completions; `say` prints it in the audit line as `usage` (`input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`) with `model_calls`. The scripted and stub models report zeros. mem0's own extraction and embedding calls are not in the audit; the README says so. |
| 3 | Who approves? | `--approve auto` (default) approves every pending proposal in id order after each turn; the membrane's invariants are the guard and every refusal is recorded. `--approve ask` prints each proposal and reads `approve` or `reject <reason>` from stdin, which is the pilot the issue describes. The runs recorded here use `auto`, and the README says so. |
| 4 | Which words? | Exactly `LITURGY` in `tests/support_embryo.py`, moved to `membrane.liturgy` so both the tests and the driver import one text; the counter is invoked with `count` twice, as Phase 14 does. The hatcher's key is generated per run with comment `mike`, and turn 2 carries `ssh-ed25519 <key> mike`, the way a real key names its owner. |
| 5 | Which door for the public turns? | `POST {MSHKN_API_URL}/ingress/{rule_id}`, as Phase 14 does: the measure is about the model, not DNS. |
| 6 | What happens when a turn does not produce its outcome? | The run continues; the postconditions decide. A `failed` build triggers turn 3 (root `say "check your build"`), at most three times per turn. A closed door makes every public turn a one-line refusal with no model call. |
| 7 | Evidence layout | `docs/embryo/<date>-run-<n>/`: `run.json` (model, times, usage, cost, verdict with evidence per postcondition), `transcript.md`, `final-list.json`, `commands/NNN-<door>-<command>.json` (every command sent, including every `list`, with its raw stdout). `docs/embryo/README.md` tabulates the runs. |
| 8 | Teardown | Mirrors Phase 14: the rule, the key, every checkpoint on `brain`, on verb chains or from a proposal's recipe, then the recipes. `--keep` skips it. A run refuses to start if the account already has a `brain` checkpoint. |
| 9 | N | Three runs first, recorded as they fall; more if the first three disagree. Runs are sequential: one account has one `brain`. |

### Task 4: `membrane.measure`: the doors

**Files:** `embryo/membrane/measure.py`, `tests/unit/test_embryo_measure.py`.

**Interfaces:** `class Doors` over an `httpx.AsyncClient` (authenticated) and a plain one: `root(*argv) -> str` (fork by label, 409 retried until `TURN_TIMEOUT`), `root_say(text) -> tuple[audit, reply]`, `public_say(payload) -> tuple[audit, reply]`, `listing() -> dict`, `wait_builds() -> dict` (list until nothing is `building`, `BUILD_TIMEOUT` 600 s), `computer_gone(cid) -> bool`, `exec_log(cid) -> dict`, `recipes() -> set[str]`, `checkpoints(label) -> list`, `teardown(hatched, listing)`. Every command goes through one `send(door, command)` that appends to `Doors.sent: list[tuple[str, str, str]]` and calls `Record.command`. Tested with `httpx.MockTransport` handlers.

- [ ] Tests: a 409 then 200 on fork; a public say whose principal is recorded; `wait_builds` returns when nothing builds; teardown deletes in order and swallows failures; implement; commit.

### Task 5: `membrane.measure`: the run and the verdict

**Files:** `embryo/membrane/measure.py`, `tests/unit/test_embryo_measure.py`.

**Interfaces:**
- `sign(key_dir, message) -> dict` (ssh-keygen -Y sign with namespace `mshkn`), `new_key(key_dir) -> str` (ed25519, comment `mike`, returns `type key mike`).
- `Approver` protocol: `decide(proposal_doc) -> str | None` (`None` approves; a string rejects with that reason). `AutoApprover` returns `None`; `AskApprover(input, output)` prints and reads.
- `async speak_liturgy(doors, key_dir, pubkey, approver) -> list[Turn]`: the turn script of Decision 6.
- `verdict(turns, final, recipes_after, preexisting, hatched_recipe, computer_checks) -> dict[str, dict]`: seven entries, each `{"ok": bool, "evidence": ...}`; `computer_checks` is what `Doors` fetched for the page_title and count computers (`gone`, `stdout`).
- `async run_once(settings, out_dir, approver, keep) -> dict` (hatches, speaks, judges, records, tears down; returns the summary).
- `main(argv)`: `--runs N`, `--approve auto|ask`, `--out docs/embryo`, `--env .env`, `--keep`, `--model claude-opus-5`.

- [ ] Tests over a fake `Doors` that plays the scripted membrane's outcomes (from a table of canned outputs): the happy path yields seven `ok`; a run whose hook never builds yields `authentication.ok is False` and continues; a failed build triggers turn 3 at most three times; `AskApprover` rejects on `reject nope`; `verdict` on fixtures; implement; commit.
