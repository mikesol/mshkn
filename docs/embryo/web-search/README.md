# The measure of web-search

`embryo/capabilities/web-search.md` is the first capability whose credential outlives its run. It starts from hatch's promotion (`docs/embryo/hatch/PROMOTED.md`), not security's — the secret path is the driver's, so nothing about security's promotion is needed and the two lineages stay independent — and asks, through the signed door, for a verb that searches the web through a provider whose API key is the *operator's* — not a secret the run minted for itself — for a search run on that verb's chain, for a second verb that reads any URL, and for that verb to read a page this repository serves.

The six postconditions it names are the three invariants (`root_unforgeable`, `no_undeclared_capability`, `nothing_by_hand`, in `embryo/membrane/postconditions.py`), the membrane's `no_foreign_credential_on_brain`, and its own two (`searched`, `read_page`, in `embryo/capabilities/web-search.py`). This directory is the evidence: each run is one directory written by `uv run capability run web-search` (`embryo/membrane/capability.py`), and `PROMOTED.md` names the run dependents start from once one is promoted.

## What is different about this credential

Security's token was minted by the capability's own module for a page the same module served, so a leak cost nothing outside the run. The provider key here is bought, rate-limited and shared with whatever else the operator uses it for, which makes three things worth reading in every run:

- **Where it comes from.** `prepare` reads SEARCH_API_URL and SEARCH_API_KEY from the `.env` beside the driver, under the environment, and refuses to start without them — a run that would place nothing must not start, and must not start after it has made a computer. Which provider is in two places only: that variable's value and the URL the rows speak.
- **Whether the agent needed it.** `searched` requires row 11's record to hold an attempt made before the key was placed and unable to succeed. Without that clause a verb that never sent the key at all would pass. Two things count and the row asks for neither by name: the provider's 401 or 403, or a trial of the verb on its own chain that exited non-zero — the verb refusing to run without its secret. Demanding the 401 would demand a verb that sends an unauthenticated request, which is the opposite of what this capability is about; run-1 produced exactly the good behaviour the first draft of the check punished. Row 11 invites the attempt and does not command it, so whether a model offers one is a real question the runs answer.
- **What the check asserts.** `searched` asserts the shape of an answer and the provenance of the call, never what the web said. It finds *every* JSON document that starts anywhere in the verb's output, outermost first, and counts the mappings carrying a URL; no provider's field names appear in it. Every document, not the first: `/exec_log` stores at most `EXEC_LOG_OUTPUT_BYTES` (`src/mshkn/services/lifecycle.py:38`), head and tail with the middle cut out, so a verb that pretty-prints a large response has its outer object destroyed while whole result objects survive inside the head. A postcondition that asserted the content of a search result is one that fails when the web changes.

Row 14 reads this capability's own page (`embryo/membrane/page.py`), served openly on a computer of its own, so that "it read a page" is judged against a body this repository controls rather than against whatever the live web was serving that minute. Row 15 is scored by nothing but the invariants: what an agent does with a verb it may point at any URL is a question for the transcript.

## The result

**Run-6 passed 6/6 and is promoted** (`PROMOTED.md`): `openai/gpt-5.6-sol` through the Vercel gateway, 42 model calls, 138 commands, $0.51. The provider is Tavily, on the operator's key. Row 12's search ran on the verb's chain from a computer that is now gone and returned five results; row 14 returned this repository's own page body.

It took six runs, and the four that failed are why the checks say what they say. None of them failed because the agent could not do the work.

- **run-1 — 5/6, `searched` NOT.** The agent's verb read its secret path, found nothing, and exited 3 before it ever reached the provider: correct behaviour, and there was no 401 to find. Worse, the clause was unsatisfiable from the day it was written. `tool_computers` returns only audit entries with a *top-level* `computer_id`, and a `try` has none — its computers are nested under `runs[]` — so the check read zero exec logs. The flow test was green only because the scripted reply text happened to contain "401" and the reply is the fallback. Fixed by `trial_runs` (`embryo/membrane/postconditions.py`), added beside `tool_computers` rather than folded into it so that no existing check silently changes what it reads.
- **run-2 — aborted at the brain guard.** `--keep` is required to be promotable, so every promotable run leaves a working brain, and `run_once` refuses to start while one is there. Correct for a run that passed, wrong for one that failed. Filed as [#193](https://github.com/mikesol/mshkn/issues/193) — since fixed: `--keep` now writes down which run's brain it left (beside the keys, never in the repository), and the next run's guard reads that run's `run.json` and tears the brain down if it failed. It refuses whenever root cannot say whose brain it is: no note, a note written against another server, or a record it cannot read. The teardown happens at the *start* of the next run rather than the end of the failed one, so a failed run's brain survives to be booted and asked what it thought it was doing.
- **run-3 — killed mid-flight, no `run.json`.** The account was left wedged and `capability teardown` could not recover it, because a run's record is the only thing that names what it made. It turns out a *dependent* can be recovered without one: it forks the lineage's promoted brain and speaks through the lineage's rule and key, all three of which are in that capability's `PROMOTED.md`. `_interrupted` and `_last_listing` (`embryo/membrane/capability.py`) read those rather than guessing; a hatch run is still refused, because its rule, key and recipe are its own creations and deleting nothing is the safe answer.
- **run-4 — 5/6, `searched` NOT, for a new reason.** The row-11 clause now passed. But the verb returned five real results and the check counted zero: the agent pretty-printed its response, `/exec_log`'s head-and-tail truncation cut the outer object open, and the first thing that decoded in the wreckage was the `[]` of an empty `images` field. Fixed by scanning for every document rather than the first. The substrate is not at fault — 8192 is not the defect, and it reports the cut out of band in `stdout_truncated`; the embryo simply drops that field, which is [#196](https://github.com/mikesol/mshkn/issues/196).
- **run-5 — aborted, no verdict.** The agent misread where the secret goes and provisioned the key at three paths in turn, rebuilding the verb each time and burning all of row 14's repairs; then `membrane root list`, on its 248th call, was SIGKILLed inside the guest at 29 s and surfaced as `exit -1` with empty stdout and stderr. The host's own timeout is 300 s and it logged no kill, so the host cannot see what happened. [#197](https://github.com/mikesol/mshkn/issues/197).

Two of those four are checks that failed a good agent, which is the failure mode worth naming: both times the first instinct was to read the run as the model's fault, and both times the check was wrong. The rule that fell out is that a postcondition must not name the mechanism it expects — not the provider's status code, not the shape of the output — only the thing that had to be true.
